# Notify Terminal

コマンドラインから Windows のトースト通知を送り、届いた通知をタスクバーの未読バッジと一覧ウィンドウでまとめて管理するアプリです。

ビルドの完了、長い処理の終了、AI エージェントの作業完了などを、1 つの場所に集めて受け取れます。

```bash
nterm send --title "ビルド完了" --body "app-x のビルドが成功しました" --open "https://example.com/runs/123"
```

- トーストが表示され、クリックすると指定した URL やファイルが開きます。
- タスクバーのアイコンに、未読の件数がバッジで表示されます。
- アプリのウィンドウには、届いた通知が一覧で残ります。

## 動作環境

- Windows 10 バージョン 1809 以降、または Windows 11
- x64

.NET や Windows App SDK のランタイムはアプリに同梱されているため、別途インストールする必要はありません。

## インストール

[Releases](https://github.com/tcdhry-public/notify-terminal/releases/latest) から、次のファイルをダウンロードします。

| ファイル | 内容 |
| --- | --- |
| `NotifyTerminal_<バージョン>_x64.msix` | アプリ本体のインストーラー |
| `NotifyTerminal.cer` | 署名に使った証明書(公開鍵) |

このアプリは自己署名の証明書で署名されているため、初回だけ証明書を信頼済みとして登録する必要があります。登録しないと、インストーラーに「発行元の証明書を確認できませんでした」と表示され、インストールできません。

1. 証明書を登録します。次のどちらかの方法で行います(管理者の権限が必要です)。
   - **PowerShell で登録する**: 管理者として PowerShell を開き、次を実行します。

     ```powershell
     Import-Certificate -FilePath "<ダウンロードした場所>\NotifyTerminal.cer" -CertStoreLocation "Cert:\LocalMachine\TrustedPeople"
     ```

   - **画面から登録する**
     1. `NotifyTerminal.cer` をダブルクリックし、「証明書のインストール」を押します。
     2. 保存場所は「ローカル コンピューター」を選びます(「現在のユーザー」ではインストールできません)。
     3. 「証明書をすべて次のストアに配置する」を選び、「参照」から「信頼されたユーザー」を選んで、完了まで進めます。
        「証明書の種類に基づいて、自動的に証明書ストアを選択する」を選ぶと、別のストア(「中間証明機関」など)に入ってしまい、インストールできません。必ず「信頼されたユーザー」を手動で選んでください。

2. `.msix` ファイルをダブルクリックし、「インストール」を押します。

インストールすると、スタートメニューに「Notify Terminal」が追加され、どのターミナルからでも `nterm` コマンドが使えるようになります(PATH の設定は不要です)。

> スマート アプリ コントロールが有効な PC では、自己署名のアプリがブロックされる場合があります。

## 更新

新しいバージョンは [Releases](https://github.com/tcdhry-public/notify-terminal/releases) で公開します。新しい `.msix` をダウンロードしてダブルクリックすると、上書きで更新されます。届いた通知と設定はそのまま引き継がれます。証明書の登録をやり直す必要はありません。

アプリは、起動の 2 分後と、その後 12 時間ごと(確認できなかったときは 1 時間後)に、新しいバージョンが公開されていないかを GitHub に問い合わせます。新しいバージョンがあると、一覧ウィンドウの右上に「〇.〇.〇 に更新できます」と表示され、押すとダウンロードページが開きます。設定画面の「今すぐ確認」で、手動で確認することもできます。

## 使い方

### 通知を送る

```bash
nterm send --title <タイトル> [--body <本文>] [--open <対象> | --exec <コマンド>]
           [--app <アプリ>] [--project <プロジェクト>] [--topic <トピック>] [--replace]
```

| オプション | 内容 |
| --- | --- |
| `--title` | 通知のタイトル(必須) |
| `--body` | 通知の本文(省略可。省略するとタイトルだけの通知になります) |
| `--open` | クリックしたときに開くもの。URL、ファイル、フォルダ、アプリのリンク(`vscode://...` など)を、関連付けられたアプリで開きます |
| `--exec` | クリックしたときに実行するコマンド。`cmd.exe` で実行され、コンソールの窓は出ません。`&&` でつないで複数の処理もできます |
| `--app` | 送信元のアプリ(省略可。例: `claude`、`github-actions`) |
| `--project` | 通知の対象のプロジェクト(省略可。例: リポジトリ名) |
| `--topic` | アプリやプロジェクトの中の単位(省略可。例: セッション、ジョブ、ブランチ、ホスト名) |
| `--replace` | 同じ送信元の古い通知を、この通知で置き換えます(下記) |
| `--json` | 上記の内容を JSON で渡します(下記) |

`--open` と `--exec` はどちらか一方だけ指定できます。どちらも省略した場合、クリックしても既読になるだけです。

`--app` / `--project` / `--topic` は、通知の送信元を表します。どれも独立していて、必要なものだけを指定できます。指定したものは、トーストの下部と一覧の各行に `claude · project-a · session a` のように表示されます。各項目は 50 文字までです。

`--replace` を付けると、同じく `--replace` を付けて送った通知のうち、`--app` / `--project` / `--topic` がすべて同じものを削除してから追加します。「ビルド中」→「ビルド完了」のように、状態が変わるたびに送る通知を最新の 1 件だけにしたいときに使います。

- 削除するのは、未読・既読を問いません。通知センターのトーストも消えます。
- 未指定の項目は、未指定どうしでだけ一致します(例: `--topic` なしで送ると、`--topic` ありの通知は置き換えません)。大文字と小文字は区別します。
- `--replace` を付けずに送った通知は、置き換えません。
- `--app` / `--project` / `--topic` のどれも指定しないと、エラーになります。

成功すると、通知の ID が表示されます。

#### 例

```bash
# URL を開く(& を含む URL もそのまま渡せます)
nterm send --title "デプロイ完了" --body "production" --open "https://example.com/runs?id=1&tab=log"

# フォルダを開く
nterm send --title "出力完了" --body "レポートを書き出しました" --open "C:\work\reports"

# VSCode でフォルダを開く
nterm send --title "テスト完了" --body "すべて成功" --exec "code C:\work\app-x"

# 送信元を付ける
nterm send --title "ビルド完了" --app github-actions --project app-x --topic build

# 同じ送信元の古い通知を置き換える(「ビルド中」が消えて「ビルド完了」だけが残る)
nterm send --title "ビルド中" --app github-actions --project app-x --topic build --replace
nterm send --title "ビルド完了" --app github-actions --project app-x --topic build --replace
```

#### JSON で送る

プログラムやスクリプトから送るときは、JSON 形式が便利です。

```bash
nterm send --json '{"title":"ビルド完了","body":"app-x","action":{"open":"https://example.com/runs/123"}}'
```

```json
{
  "title": "ビルド完了",
  "body": "app-x",
  "action": { "open": "https://example.com/runs/123" },
  "app": "github-actions",
  "project": "app-x",
  "topic": "build"
}
```

- `title` 以外の項目(`body`、`action`、`app`、`project`、`topic`、`replace`)は省略できます。`replace` は `true` / `false` で指定します。
- `action` には `open` か `exec` のどちらか一方を書きます。
- JSON の中で Windows のパスを書くときは、バックスラッシュを `\\` と 2 つ重ねるか、スラッシュ区切り(`C:/work/app-x`)で書いてください。スラッシュ区切りのほうが、シェルを通しても崩れにくく安全です。

#### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 成功 |
| `1` | 引数や JSON の誤り |
| `2` | アプリに接続できなかった |

アプリが起動していないときに `nterm send` を実行すると、アプリが自動で(最小化された状態で)起動してから通知が届きます。

### 受け取った通知を見る

- **トースト**: 通知が届くと、画面右下にトーストが表示されます。クリックすると、`--open` / `--exec` で指定したアクションが実行され、その通知は既読になります。トーストは通知センターにも残ります。
- **タスクバーのバッジ**: 未読の件数が、タスクバーのアイコンに数字で表示されます。
- **一覧ウィンドウ**: タスクバーかトレイのアイコンをクリックすると、届いた通知が新しい順に並んだウィンドウが開きます。
  - 行をクリックすると、アクションが実行されて既読になります(既読の行は薄く表示されます)。設定で、クリックでは展開するだけにしたり、ダブルクリックで実行するようにしたりできます。
  - 行の右のボタンで、次の操作ができます。
    - ⌄: 行を展開して、開く対象や実行するコマンドを全文で表示します。実行する前に確かめられます。
    - ▶: アクションを実行して既読にします。
    - ✓: アクションを実行せずに既読にします。
    - ゴミ箱: 削除します。
  - キーボードでも操作できます: ↑↓ で移動、Enter で展開・折りたたみ、Ctrl+Enter でアクションを実行、Esc で既読にする、Delete で削除。
  - 上部の「すべて既読にする」「既読をすべて削除」で、全体をまとめて操作できます(実行前に確認があります)。
  - 左上のドロップダウンで、アプリやプロジェクトごとにまとめて表示できます(「アプリ › プロジェクト › トピック」のように階層にもできます)。見出しの「既読にする」「既読を削除」で、そのグループをまとめて操作できます(削除は実行前に確認があります)。
  - 一覧で既読にした通知や削除した通知は、通知センターのトーストからも消えます。
  - 通知センターで × を押したり「すべてクリア」したりしても、一覧の未読は変わりません。未読はアプリの一覧を基準に管理しています。

### 設定

ウィンドウ右上の `⋯` メニューから「設定」を開きます。変更はすぐに保存されます。

| 設定 | 内容 |
| --- | --- |
| トーストのクリックでアクションを実行する | オン(既定): トーストのクリックで、`--open` / `--exec` のアクションを実行して既読にします。<br>オフ: アクションは実行せず、一覧ウィンドウを開いてその通知を強調表示します(未読のまま)。アクションは一覧から実行できます。 |
| 一覧の通知のクリックでアクションを実行する | オン(既定): 一覧の行のクリックで、アクションを実行して既読にします。<br>オフ: クリックでは行を展開して、開く対象や実行するコマンドを表示します(もう一度クリックすると閉じます)。 |
| 一覧の通知のダブルクリックでアクションを実行する | オフ(既定): ダブルクリックでは実行しません。アクションは ▶ のボタンか Ctrl+Enter で実行します。<br>オン: ダブルクリックで、アクションを実行して既読にします。<br>クリックで実行する設定のときは使えません。<br>オンのときは、ダブルクリックかどうかを見分けるため、クリックでの展開が少し(ダブルクリックの間隔の分だけ)遅れます。 |
| ダブルクリックの間隔(ミリ秒) | 空欄(既定): Windows の設定(コントロールパネルの「マウス」のダブルクリックの速度)に従います。<br>数値を入れると、一覧ではその間隔でダブルクリックを判定します(100〜2000)。短くすると、クリックでの展開の遅れも短くなります。<br>ダブルクリックで実行する設定のときだけ使えます。 |
| 一覧の通知を展開して表示する | オフ(既定): 通知は閉じた状態で表示します。<br>オン: すべての通知を展開した状態で表示し、開く対象や実行するコマンドを最初から見られるようにします。<br>どちらでも、通知ごとに展開・折りたたみできます。 |
| ログオン時に自動で起動する | オン(既定): Windows にサインインしたとき、ウィンドウを開かずトレイに常駐した状態で起動します。<br>Windows の「設定」→「アプリ」→「スタートアップ」からも切り替えられます。Windows 側でオフにした場合は、そちらでオンに戻してください。 |
| 更新を自動で確認する | オン(既定): 新しいバージョンを定期的に確認します([更新](#更新) を参照)。<br>オフ: 自動では確認しません。設定画面の「今すぐ確認」は使えます。 |
| 通知の保持期間 / 既読通知の保持期間 / 保持する通知の件数 | 自動で削除するまでの日数と、保持する件数です(既定は 30 日 / 7 日 / 1000 件)。「無制限」にもできます。変更はすぐに反映されます([通知の保存と自動削除](#通知の保存と自動削除) を参照)。 |
| 受信した通知をアーカイブに保存する | オフ(既定): アーカイブには保存しません。<br>オン: 受信した通知を、一覧とは別にアーカイブにも保存します([アーカイブ](#アーカイブ) を参照)。 |

### トレイへの常駐と終了

- アプリは起動している間、通知領域(トレイ)にアイコンを表示します。
  - 左クリック: 一覧ウィンドウを開きます。
  - 右クリック: 「開く」「Notify Terminal を終了」のメニューを表示します。
- ウィンドウの × を押しても、アプリは終了せずトレイに残ります。通知は引き続き受け取れます。
- ウィンドウを閉じている間に通知が届いたり、トーストをクリックしたりすると、ウィンドウが最小化された状態でタスクバーに戻ります。作業中のウィンドウからフォーカスは奪いません。
- アプリを終了するには、ウィンドウ右上の `⋯` メニューか、トレイのアイコンの右クリックメニューから「Notify Terminal を終了」を選びます。終了したあとでも、`nterm send` を実行すると自動でまた起動します。

### 通知の保存と自動削除

- 通知はアプリ内に保存され、アプリを終了・再起動しても残ります。
- 次の通知は、自動で削除されます。日数と件数は設定画面で変えられ、それぞれ「無制限」にもできます。
  - 受信してから 30 日経った通知(未読も含む)
  - 既読になってから 7 日経った通知
  - 1000 件を超えた分(古い既読の通知から削除し、既読がなければ古い未読から削除)

### アーカイブ

設定で「受信した通知をアーカイブに保存する」をオンにすると、受信した通知を、一覧とは別に月ごとのファイルにも保存します。一覧から削除した通知や、自動で削除された通知も、アーカイブには残ります。

- 保存先は、設定画面の「アーカイブのフォルダを開く」で開けます。
  - 場所: `%LOCALAPPDATA%\Packages\NotifyTerminal_ehfrhx0sg97pg\LocalState\archive`
  - ファイル名: 受信した月ごとの `2026-10.jsonl` のような名前で、1 行に 1 件の JSON です。
- 受信した時点の内容を保存します。既読になったかどうかは記録しません。
- アーカイブのファイルは自動では削除しません。不要になったら、ファイルを削除してください。
- オンにする前に受信した通知は保存されません。
- アプリをアンインストールすると、アーカイブも一緒に削除されます。残したい場合は、先にフォルダをコピーしてください。

## シェルごとの注意

- **Git Bash**: `/` で始まる引数は、Windows のパスに自動で変換されます(例: `/deploy` → `C:/Program Files/Git/deploy`)。値が `/` で始まる場合は、`MSYS_NO_PATHCONV=1 nterm send ...` のように実行するか、`--json` を使ってください。
- **Windows PowerShell 5.1**: exe に渡す引数の中の `"` が落ちるため、`--json '<JSON>'` が壊れます。オプション形式(`--title` など)を使ってください。

## アンインストール

「設定」→「アプリ」→「インストールされているアプリ」から「Notify Terminal」をアンインストールします。保存している通知も一緒に削除されます。

登録した証明書を削除する場合は、管理者の PowerShell で次を実行します。

```powershell
Get-ChildItem Cert:\LocalMachine\TrustedPeople | Where-Object Subject -eq "CN=tcdhry-localhost" | Remove-Item
```
